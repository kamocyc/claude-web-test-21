# 都市開発シミュレーション

日本を舞台にしたエージェントベースの都市シミュレーションゲーム（TypeScript + Three.js）。

市民を 1 人ひとり個別にシミュレートします。各市民は年齢・職業・学歴・所得・交通手段の好みを持ち、
自宅から職場へ通勤し、買い物やレジャーに出かけます。どの交通手段で行くかは、
実際に経路探索した所要時間・運賃・その人固有の好みから多項ロジットで決まります。

産業は田んぼと林業を起点としたサプライチェーンを持ち、
トラックが市民と同じ道路網を走って資材を運びます。

```
npm install
npm run dev          # ブラウザで遊ぶ
npm test             # テスト一式（86 件）
npm run sim:headless -- --days 180   # 描画なしでシミュレーションだけ回す
```

---

## 遊び方

起動すると 2 つの入口が出ます。

- **何もない土地から始める（チュートリアル付き）** — 道路 1 本から街をつくります
- **できあがった街を見る** — 仕組みが動いているところをすぐ眺めたいとき

### 画面

Cities: Skylines の配置に寄せてあります。

| 位置 | 内容 |
|---|---|
| 左上 | 都市名・人口・資金・**月次収支**・幸福度・失業率／日時と時間速度 |
| 右上 | マイルストーン（人口で解禁されるもの） |
| 下中央 | ツールバー（カテゴリを選ぶと道具が上に出る） |
| 右下 | RCI 需要バー（住・商・工・農）と情報表示の切替 |
| 左 | 選んだ市民・建物の詳細 |
| 左下 | チュートリアル |

| 操作 | |
|---|---|
| 画面移動 | Alt + ドラッグ / WASD / 矢印キー（いずれもカメラの向き基準） |
| 回転 | 右ドラッグ / Q・E |
| ズーム | ホイール |
| 時間速度 | 1〜4 キー、スペースで一時停止 |
| 選択解除 | Esc |

時間速度は **×1 / ×4 / ×20** で、1 日がそれぞれ実時間 32 分 / 8 分 / 1.6 分です。
×1 は街を眺めるための速度で、人も車も電車も現実的な速さに見えます。
発展させたいときは早送りしてください（早送り中は当然その分だけ速く見えます）。

道具はカーソル横に費用と可否（「ここには敷けません」など）が出ます。

### 近景に映るもの

ズームインすると、街に人と車両が出ます。

| | いつ出るか |
|---|---|
| 歩行者・自転車 | カメラ距離 460m 未満。移動中の人は経路上を実際に進む。屋外に立たせるのは**買い物中とレジャー中だけ**（在宅・勤務・通学は屋内にいる扱い） |
| 自家用車（走行中） | 車で移動中の市民。左側通行で車線に寄せて走る |
| 自家用車（駐車） | カメラ距離 900m 未満。車を持つ市民の車を、その人が今いる場所（車で来ていなければ自宅）の路肩に停める |
| トラック | 物流のトラック。**積荷ごとに色が違う**ので、何がどこへ流れているかが街を見るだけで分かる。帰路は空車色 |
| 電車 | 線路の上を 3 両編成が往復する（先頭車だけ色が濃い）。駅が 1 つも無い線路には走らない |

駐車中の車を描いているのは、車の大半が 1 日のほとんどを停まって過ごすからです。
走行中だけだと、街に映る自家用車が実態よりずっと少なくなります。

### マイルストーン

人口が増えるにつれて道具が解禁されます。最初から全部渡されても何をすればいいか分からないので、
「次に何ができるようになるか」が街を育てる動機になるようにしてあります。

| 人口 | 呼称 | 解禁 |
|---|---|---|
| 0 | 開拓地 | 生活道路・低層住居・畑・公園・役所 |
| 40 | 集落 | 近隣商業・水田・林業・交番 |
| 150 | 村 | 二車線道路・準工業・学校 |
| 400 | 町 | **鉄道・駅**・消防署・中高層住居 |
| 1,000 | 市 | 大通り・商業地域・工業地域・病院・神社 |
| 3,000 | 中核市 | オフィスビルが建つ |
| 6,000 | 中核都市 | タワーマンションが建つ |

### チュートリアル（全 10 段階）

説明を読ませるのではなく、街の状態を見て達成したら次に進みます。
道路 → 用途地域 → 住民 → 職場 → お店 → 食料の自給 → 公共施設 → 鉄道 → 木材の自給、
という順にこのゲームの因果関係をひととおり体験できます。

**確認しておくと面白いところ**

- **近景で住民と車両が見えます** — カメラを寄せると、通りに人が立ち、通勤時間帯には歩道を歩きます。
  路肩には自家用車が並び、トラックが積荷の色で走り、線路の上を電車が往復します（すべて実寸）。
- **市民インスペクタ** — 「選択」ツールで市民をクリックすると、その人の年齢・職業・自宅・職場・
  今日の行程に加えて、**直近の交通手段選択の内訳**（各手段の所要時間・運賃・選択確率）が出ます。
  「1 人ひとりをシミュレートしている」ことがその場で確認できます。
- **経路確認ツール** — 2 点をクリックすると、その間の経路探索結果が地図上に赤い線で描かれます。
  道路を 1 タイル壊してからもう一度試すと、迂回路に切り替わります。
- **建物インスペクタ** — 工場や商店をクリックすると、在庫・**現在の仕入先**・欠品日数が見えます。
  物流が滞っている原因を追えます。
- **情報表示** — 地価・交通量・用途地域・公害・鉄道アクセスをヒートマップで重ねられます。

## 設計

### レイヤ

```
src/sim/     シミュレーション本体。three.js も DOM も一切参照しない
src/render/  three.js による描画。sim を読むだけで、書き換えない
src/ui/      日本語 UI。sim には Command を発行するだけ
src/app/     3 者を配線してゲームループを回す
```

`sim` が描画から完全に独立しているので、Node 上でそのままテストでき、ヘッドレスで
何百日分でも回せます。テストの 86 件はすべてブラウザなしで動きます。

プレイヤ操作はすべてシリアライズ可能な `Command` として表現し、tick 境界でのみ適用します。
シード＋コマンド列があれば同じ街が再現できるため、決定論テスト・セーブデータ・
不具合の再現手順が同じ仕組みから得られます。

### 1 万人を個別に動かすための仕掛け

素直に作ると必ず性能の壁にぶつかる箇所が 3 つあり、それぞれ対策を設計に埋め込んであります。

**1. 毎 tick 全市民をループしない — タイミングホイール**

各市民は「次に何かが起きる tick」だけを持ち、その tick のバケツに入ります
（`sim/core/timeWheel.ts`）。1 人あたり 1 日 6〜10 イベント（起床・出発・到着・退勤・買い物・帰宅）
なので、1 万人でも **1 tick あたり平均 50〜70 件**しか処理しません。
在宅中・勤務中の市民は文字通りゼロコストです。

**2. 意思決定に経路探索を使わない — TAZ コスト行列**

「どこで働くか」「どこで買い物するか」「どの交通手段にするか」「どの工場から仕入れるか」は
所要時間の概算しか必要としません。ゾーン間のコスト行列（`sim/network/tazMatrix.ts`）を
ローリング更新しておき、これらの判断は配列参照 1 回で済ませます。
実際の A* が要るのは「本当に移動する経路が必要」なときだけです。

**3. 経路キャッシュと探索予算**

キャッシュのキーは建物ではなく**道路ノード**です。40 世帯のマンションも 200 人のオフィスも
接道点は 1 つなので、ヒット率が跳ね上がります（人口 7,000 の街で実測 98.8%）。
容量は 12 万件。ここが足りないと追い出しが常時起きてヒット率が 75% まで落ち、
1 tick の処理時間が 1.3ms まで悪化します（実際に踏みました）。
さらに 1 tick あたりのノード展開数に上限を設け、溢れた市民は「出発準備」状態で待たせます。
プレイヤが幹線道路を撤去した瞬間に全市民が一斉に再探索してフレームが飛ぶ、という事故を防ぎます。

**重要な規約: 混雑ではキャッシュを捨てません。** キャッシュしているのは「経路」であって
「所要時間」ではありません。混雑で無効化すると、交通量が最大のまさにその瞬間に
キャッシュが全滅して探索が爆発します。

### 1 日のトリップと朝夕のラッシュ

市民は生活パターンのテンプレート（`sim/agents/schedules.ts`）を 1 つ持ち、
そこに **ID から決まる固定のジッタ**を足した時刻に動きます。ジッタが固定なのは、
毎日同じ人が同じ時刻に同じ経路を通ることで経路キャッシュが効くからです。

- 会社員（8:00 出勤 / 13:00 業務移動 / 18:30 買い物 / 19:30 レジャー / 20:30 帰宅）
- 早番（6:30 出勤 / 16:00 買い物 / 17:00 帰宅）、夜勤（21:30 出勤 / 6:30 帰宅）
- 学生・主婦主夫・高齢者・無職

**寄り道を「しない」と決めたときに、その場に留めるのが要点です。**
以前はここで自宅に `settleAt` していました。すると勤務先にいる市民が自宅に瞬間移動し、
**帰宅トリップそのものが発生しません**。会社員は買い物 40%・レジャー 25% で寄り道するので、
両方外した 4 割強が夕方に職場から消えて家に湧いていて、夕ラッシュが半分になっていました。
症状は「夕方なのに道路が空いている」だけなので、これは統計を見ないと気付けません。

同じ種類の見落としがもう 1 つあり、`ScheduleKind.ShiftWorker` はテンプレートが
書かれているのに `pickSchedule` に分岐が無く、一度も割り当てられていませんでした。

### 交通手段の選択

各手段の所要時間・運賃・駐車探索時間を体感分に換算し、多項ロジットで確率的に選びます。

```
GC_m = 体感所要分 + 運賃 / 時間価値 + 駐車探索分
U_m  = -GC_m + モード固有定数 + その人の好み + 目的別バイアス
P(m) = exp(U_m/θ) / Σ exp(U_k/θ)
```

- 好みは市民ごとに生成時に一度だけ引き、生涯変わりません
- 時間価値は所得に比例します（金持ちほど時間を金で買う）
- 自動車は 18 歳以上かつ保有者のみ、鉄道は両端が駅の徒歩圏にある場合のみ
- 都心ほど駐車探索時間が長く、自動車が不利になります
- **定期券**を持つ勤め人は通勤の鉄道運賃が 0 になり、鉄道分担率を強く押し上げます

argmax ではなく確率的に引くのが要点です。同条件の市民が全員同じ選択をすると、
交通量が全か無かで振れて街が壊れて見えます。分担「率」として出したいので抽選します。

### 渋滞

BPR 遅延関数 `t = t0 (1 + α (V/C)^β)` で混雑を所要時間に反映します。
発振を防ぐ仕掛けが 3 つ入っていて、どれか 1 つでも欠けると経路が毎回入れ替わります。

1. 経路探索が読むのは EMA 平滑化済みのコストだけ
2. 走行中に再探索するのは、遅延が閾値を超えた市民のうち約 10% だけ
3. 市民ごとに ±5% の固定的なコスト摂動（等コストの並行路に流れを分散させる）

### サプライチェーンと物流

```
田んぼ ──米──┐
              ├─→ 食品工場 ──食品──→ 商店・コンビニ・スーパー ──→ 市民の買い物
畑     ──野菜─┘

林業区画 ──原木──→ 製材所 ──木材──┬─→ 建物の建設が消費（街の成長速度を律速する）
                                    └─→ 町工場・工場 ──日用品──→ 商店
```

- 水田は **9 月に一年分がまとめて穫れます**。倉庫の必要性と、毎年決まった時期の物流の山が生まれます
- 消費側の在庫が減ると発注し、供給元からトラックが出ます。トラックは市民と同じ道路グラフを A* で走り、
  **同じエッジの交通量に加算されます**。工場を市街地の反対側に置けば、その物流が通勤路を混雑させます
- 仕入先は一度決めたら固定します（取引関係）。毎回選び直すと OD ペアが毎回変わって
  経路キャッシュが効かず、配送そのものが成立しなくなります
- 地元に木材が無い場合は輸入で賄えますが高くつきます。林業〜製材所を整備すると建設費が下がります

### 街が発展する仕組み

- **接道していない区画には絶対に建物が建ちません。** これが道路設計をゲームにする一番の要です
- 魅力度 = f(地価, **鉄道アクセス**, サービス到達, 平坦さ, 公害, 騒音)。
  鉄道アクセスの重みを地価に次ぐ大きさにしてあるのは意図的で、
  「駅を先に敷いて周りをゾーニングしたプレイヤが報われる」ようにするためです（私鉄の沿線開発）
- 建設確率は魅力度の 2 乗に比例します。良い場所から順に埋まり、条件の悪い土地は
  圧力が高まるまで空いたままになります。線形にすると全域が一様に埋まってのっぺりした街になります
- タワーマンションやオフィスビルは市の人口が一定を超えてから出現します

### 転入と建設は別の信号で決める

ここは一度間違えて、**人口が永久に 0 のまま**になった箇所です。

「空き家が多い」は *これ以上家を建てるな* という信号であって、*人が引っ越して来るな*
という信号ではありません。むしろ空き家があるからこそ移り住めます。
両方を住宅需要ひとつで判定していたため、

```
家が建つ → 全部空き家 → 住宅需要がマイナス → 誰も転入しない → 永久に空き家
```

というデッドロックに入っていました。いまは分けてあります。

- **建設**は RCI 需要（空き家が多ければ下がる）
- **転入**は「空き住戸があるか」＋「街が住むに値するか」（求人の余り・幸福度・税率）

### 業種は「原料が地元で手に入るか」で選ばれる

同じ種類のデッドロックがサプライチェーンにもありました。

- 原材料不足の工場が多いと工業需要を下げていたが、それでは**不足を解消する当の製材所**
  まで建たなくなる → 抑制はするが止めない強さに調整
- 品薄の資源を作る業種を優先するが、**原料が地元で手に入らない業種は逆に抑える**。
  これが無いと、木材が 1 単位も無い段階で町工場が準工業地を埋め尽くし、
  そのあと全部休止して食品工場の入る余地が消えます
- 「不足していない」だけでは判定できません。誰も欲しがっていない資源は不足量が 0 に
  見えるだけなので、**在庫か生産があるか**まで見ます
- 区画の隅に残った 1 マスを埋める小さい建物へのフォールバックにも同じ判定を効かせます。
  効かせないと、1×1 の町工場が区画を分断して 2×2 の食品工場・製材所が
  どこにも入らなくなります

### 距離と時計のスケール — 地図は 1/15 で描いている

`TILE_M = 10` は 1 タイルの**描画上の**大きさ、`TILE_SPAN_M = 150` は
1 タイルが**シミュレーション上で表す実距離**です。この 2 つを分けているのは、
次の 2 つを同時に成り立たせるためです。

1. 1 日が実用的な長さで進む
2. 人・車・電車が現実的な速さに見える

この 2 つは 1 本の式で結ばれていて、両立できる組み合わせは限られています。

```
1 日の実時間（分） = 19152 ÷ （歩行者の見た目の速さ[m/s] × 1 タイルの実距離[m]）
```

10m/タイルのままだと、歩行者が歩く速さに見える時計では 1 日が実時間 8 時間になり、
逆に 1 日を 2 分にすると時間が実時間の 720 倍で流れ、**電車が地図を 0.2 秒で横断**します。
150m にして初めて、1 日 32 分と現実的な速度が同時に成り立ちます。

副次的に、これまで意味を成していなかった距離がすべて現実的になりました。

| | 変更前 | 変更後 |
|---|---|---|
| 平均通勤時間 | 3 分 | 26〜39 分 |
| 駅の徒歩圏 | 120m | 1.2km |
| 自転車の上限距離 8km | 地図全体が 3.2km で**一度も効かない** | 実際に効く |
| 同時に移動している市民（人口 2000） | 4 人 | **平均 93 人・最大 733 人** |

最後の行が「街が生きて見える」かどうかを決めます。実在の都市でも移動中の人は
人口の 5% 程度で、変更前の 0.3% は距離が短すぎたせいでした。

**単位を跨ぐ箇所には必ず `SIM_PER_RENDER` を掛けること。** 特に
`Graph.straightLineM()` は A* のヒューリスティックに使われるので、掛け忘れると
ヒューリスティックが非許容になり、**A* が黙って最短でない経路を返します**。
症状は「車が変な道を通る」だけで目視では追えません。
`test/pathfinding.test.ts` の「A* の結果がダイクストラと一致する」が唯一の検出手段です。

この変更で `transitAccess`（駅までの徒歩分）が 15 倍になり、
以前は街じゅうで「徒歩 3 分」だったものが本来の値に戻りました。
その結果、地価と魅力度に常時乗っていた鉄道ボーナスが駅の近くだけに戻り、
街全体がレベルアップ閾値を下回って人口が固定されました。
地価と魅力度の基礎値でその分を補ってあります
（鉄道は人口 400 で解禁されるので、鉄道が無くても成長できる下限は必ず要る）。

### 経済の時間だけデフォルメする

距離と時計を作り直した結果、1 日は実時間 2 分から **32 分**になりました。
移動の見た目はこれで正しくなりますが、**経済側は「1 日単位」で回ったまま**なので、
実時間で見ると転入も求職も建設判定も 16 倍遅くなります。
プレイヤから見ると「家を建てても 30 分誰も来ない」「商店を建てても就業者が 0 のまま」で、
ゲームが壊れているようにしか見えません。

1 日の長さと移動の見た目は変えずに、**経済の時間だけ**デフォルメして取り戻します。

| | 周期 | ×1 での実時間 |
|---|---|---|
| 転入・求職・雇用統計・収支 | `ECONOMY_PERIOD_TICKS` = 120 tick（2 時間） | 2.7 分 |
| 地価・サービス圏 | 日次 ＋ **プレイヤが建てた／壊した瞬間** | 即時 |
| 公害・在庫切れ・廃業・レベルアップ・加齢・出生・転居 | 日次 | 32 分 |
| 決算 | 月次 | 16 時間 |

加速するのは「**建つ・育つ・来る・雇われる**」側だけです。
廃墟化・廃業・転出の猶予日数は据え置いてあります。破壊側まで速めると、
サプライチェーンが立ち上がる前に上流が全滅する事故が起きます（実際に起きました）。

一時停止中もコマンドは適用します（`Simulation.flushCommands()`）。
`applyCommands()` が `tick()` の先頭にしか無かった頃は、停止して道路を引いても
道路が現れず、課金もされず、警告も出ませんでした。停止して街を作るのは普通の遊び方です。

求職まわりで直したものがもう 2 つあります。どちらも「就業者が 0 のまま」の原因でした。

- 求職は「市民 1 人につき 7 日に 1 回」でした。×1 では 3.7 実時間に 1 回です。
  回転カーソルで未就業者を一巡させる方式に変え、2 時間ごとに回します
- `seekJob` は TAZ 行列のコストが `Infinity` のとき**黙って候補を捨てて**いました。
  行列は 1 周 200 tick かけて埋まるので、街を作り始めた直後は採用が一切成立しません。
  移動側と同じ直線距離のフォールバックを入れ、`bootstrap()` で行列を先に埋めます

### 電車はシミュレーションではなく描画側に置く

`sim` に列車の実体はありません。鉄道は「線路エッジ ＋ 乗降エッジに載せた
`運行間隔 / 2 × 待ち時間重み`」という抽象モデルで、ここに列車オブジェクトを足しても
所要時間も分担率も 1 ミリも変わらず、決定論的状態が増えるだけです。

そこで列車は描画専用にし、位置は**モデルが既に前提にしている運行間隔と表定速度から
導出**しています（`sim/network/railLines.ts`）。飾りではなく、
モデルが値付けしている待ち時間そのものの可視化になっています。
線路の折れ線抽出も列車位置も three.js に依存しない純関数なので、ヘッドレスで単体テストできます。

線路は分岐（次数 3 以上）で切って別の線として扱います。跨いで 1 本に繋ぐと、
電車が分岐点で不自然に折り返します。

### 乗り物は「今どのエッジにいるか」で描き分ける

自動車の経路は両端に徒歩区間を含み（駐車して歩く）、鉄道の経路は両端に駅までの
徒歩区間を含みます。モードだけで見た目を決めると、**車が歩道を走り、電車が線路を降りて
歩道を歩きます**（実際にそうなっていました）。

`pathPosition()` が現在いるエッジの index を返すので、`edgeMask` を見て
車道なら車、線路なら（車内にいるので）描かない、それ以外は歩行者、と切り替えます。
おかげで「駅まで歩く鉄道利用者」が初めて描かれるようになりました。

### フィードバックループ

このゲームが「動いている」と言えるのは、プレイヤの操作が痛みや報酬として返ってくるからです。

```
道路設計が悪い → トラックが届かない → 商店の在庫が切れる
  → 市民の買い物が失敗して不満が溜まる → 転居、それでも駄目なら転出
  → 地価が下がる → 建物が廃墟になる → 税収が減る

学校・病院・交番・公園を届かせない → 幸福度が下がり続ける（基礎値はマイナス）
工場が原材料不足で止まっている → 工業需要が下がり、それ以上工場が建たなくなる
林業と製材所が足りない → 木材が輸入頼みになり、建設費がかさむ
```

需要モデルの全項は容量で正規化して範囲を clamp してあります。素の比を使うと、
この手の経済は指数的に発散するか、逆に過減衰して人口数千人で永久に止まります。

### テスト（86 件）

すべて `sim` レイヤのみで動き、ブラウザを必要としません。

| ファイル | 内容 |
|---|---|
| `test/pathfinding.test.ts` | **A* の結果がダイクストラと一致する**（500 通りのランダムネットワーク）、到達不能は null、探索予算の遵守、道路撤去で経路が変わる |
| `test/network.test.ts` | 駅が徒歩レイヤと鉄道レイヤを接続する / 駅を外すと切れる、踏切、BPR の単調性と上限、**平滑化による発振の抑制**、キャッシュの無効化とリーク |
| `test/modeChoice.test.ts` | 確率の総和、単調性、年齢・保有・距離のゲート、定期券、**抽選分布が理論値と一致する** |
| `test/simulation.test.ts` | 決定論（同一シード＋同一操作で同じ街）、**接道なしには建たない**、地形制約、サプライチェーン、在庫の非負性と上限、需要の発散しなさ、世代タグ、財政台帳 |
| `test/integration.test.ts` | 90 日運転の不変条件（後述）＋ プレイヤ操作への応答 |

`A* == ダイクストラ` の一致検査がこの中で最も価値が高いテストです。
ヒューリスティックが非許容だと A* は**黙って**最短でない経路を返し、
ゲーム上は「車が変な道を通る」としか現れないため、目視では追えません。

### 統合テストが確認している不変条件

90 日運転して以下を検査します。

- 人口が増える／1 日で 1.5 倍を超える爆発が起きない
- 市民が実際に移動を完了している（1 日の完了移動数 > 人口の半分）
- 経路探索の失敗率が 2% 未満、キャッシュヒット率が平均 80% 超
- 3 種類以上の交通手段が実際に使い分けられ、鉄道分担率が 2% を超える
- どの市民も同じ状態に張り付いたままにならない
- 市民の建物参照がすべて有効（世代タグが破綻していない）
- 就業者数が定員内、住民数が住戸容量内
- NaN / Infinity がどこにも出ない
- サプライチェーンが一巡し、トラックが 100 件以上配送している
- 1 tick の処理時間が予算内（×10 速度 = 1 フレーム 2 tick で 6ms 以内）

### ヘッドレス実行

```
npm run sim:headless -- --seed 42 --days 180 --every 20 --population 900
```

描画なしで街を組み立てて N 日回し、日次の指標を表で出します。
経済のフィードバックループが発散・停滞したときに最初に気づける場所です。

実測（200 日運転、人口 7,000）:

```

  ×10 速度は 120 tick/秒 = 60fps なら 1 フレーム 2 tick → 2.2 ms/フレーム
経路キャッシュヒット率: 98.8%（使用 10.9 万 / 上限 12 万）
経路探索の失敗: 0 件 / 38 万件
交通分担率: 徒歩 17% / 自転車 40% / 自動車 15% / 鉄道 28%
```

## 既知の制約と次の一手

- 鉄道は 1 つの連結網として扱い、路線の区別と時刻表はありません。乗換の重さは
  徒歩と鉄道の境界に載せた待ち時間・乗車ペナルティで表現しています
- 交通グラフは道路タイル 1 枚 = 1 ノードです。この規模（数千ノード）ではキャッシュと
  探索予算で十分に収まりますが、10 万人規模に伸ばすならセグメント縮約が最初の最適化対象です
- `sim` が描画から完全に独立しているので、Web Worker への移行は
  アロケータの差し替えで済む設計になっています（v1 ではデバッグしやすさを優先してメインスレッド）
- バス路線、港湾・貨物駅による輸出入、災害、観光客の流入は未実装です
- 近景の住民は、移動中の人は経路上を実際に歩きます。屋外に立たせるのは買い物中と
  レジャー中だけで、在宅・勤務・通学中の人は屋内にいる扱いにして描いていません
  （以前は全員を玄関前に立たせていて、位置が ID から決まる固定値なので
  「同じ人が一日じゅう同じ場所に立ち尽くす街」になっていました）
- 電車は描画専用で、線路を端から端へ往復するだけです。駅での停車、路線ごとの運行間隔、
  乗車人数に応じた増発はありません（鉄道モデル自体が路線を区別していないため）
- 地図は 1/15 スケールで描いています。1 タイルは実距離 150m の街区で、そこに建つ
  1 棟の箱は街区 1 つ分を表します。建物 1 棟あたりの収容人数は実距離に合わせて
  上げていないので、シミュレーション上の人口密度は実際の日本の市街地より低めです
- 早送り（×4・×20）中は、時計が速い分だけ人も車も電車も速く見えます。
  見た目とシミュレーションが完全に一致するのは ×1 のときだけです
- 車両どうしの相互作用（車間・信号待ち・追い越し）はありません。渋滞はエッジ単位の
  BPR 関数で表現していて、車両は経路長に対する一定速度で進みます
- 経済の反応速度は実時間基準に取り直してありますが、需要（RCI）の再計算だけは
  日次のままです。在庫切れ判定など「日数を数える」処理と入力を共有しているためで、
  需要バーが動くのは 1 日に 1 回です
- 業務移動の行き先は雇用のある事業所からの重力モデル抽選で、取引関係は見ていません
- セーブ／ロードの UI はまだありません（シード＋コマンド列で再現できる土台はあります）
